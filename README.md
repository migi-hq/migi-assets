# @migi/assets

MIGI 三端（`migi-web` / `migi-pos` / `migi-admin`）共用的**設計 token 與品牌美術**。

> 🔴 **這個 repo 只放資產，永遠不放碰 Supabase 的程式碼。**
> 它是公開的（見下），公開的東西一旦混進不該公開的，代價不對稱。

---

## 為什麼存在

三端各自獨立部署、沒有共用套件，所以設計值一直靠**手抄**。而手抄的東西只會抄「當下需要的」：

```
2026-08-15  統一顏色 → POS 抄了 17 個顏色 token
之後        web 長出字級／圓角／間距／陰影（27 個）→ POS 沒跟上
2026-08-29  實測：POS 有 304 個寫死 fontSize、117 個寫死 borderRadius
            而它的 var(--) 只用了 17 次
```

🔴 **那不是店員端偷懶 —— 是那份 token 從來沒送到它手上。**

而同一個值在三端有**兩種形狀**（`var(--brand)` 與 `C.brand`），在這之前那是兩份手寫的表述。這裡讓它們變成**同一份的兩個輸出**。

---

## 用法

```jsonc
// 三端的 package.json
"@migi/assets": "github:migi-hq/migi-assets#v1.0.0"
```

```js
// migi-web / migi-admin
import '@migi/assets/tokens.css'        // 定義 :root

// migi-pos（inline style 為主）
import '@migi/assets/tokens.css'
import { C } from '@migi/assets/tokens.js'
//  C.brand === 'var(--brand)' —— 吐的是變數不是色碼，見下
```

```js
// 圖檔
import bronze from '@migi/assets/bears/bear-rank-bronze.webp'
```

### ⚠ 版本用 tag 釘，不要用 branch

`#main` 會讓「同一份 package.json 在不同時間裝到不同東西」。`#v1.0.0` ＋ lockfile 記住 commit，可重現。

📌 **這不會讓三端變成一起部署。** POS 可以停在 `v1.0.0`、web 先升 `v1.1.0` —— 那是刻意的：POS 是收銀機，不該因為會員 App 改了個顏色就跟著動。

## 改東西的流程

```bash
# 1. 改 tokens.json（或換圖）
# 2. 重新產生
npm run build
# 3. commit（產出物要一起）＋ 打 tag
git tag v1.1.0 && git push --tags
# 4. 三端把 package.json 的 #v1.0.0 改成 #v1.1.0
```

⚠ **產出物 `dist/` 要 commit 進版控。** git 相依沒有 `npm publish` 的打包步驟；靠 `prepare` script 在安裝時 build 等於多一個會失敗的地方，而它失敗時的錯誤訊息指向 `npm install`，看不出真正的原因。

✅ 所以有 `npm run check`：**產出物與 `tokens.json` 不同步就 exit 1**。
「改了 tokens.json 但忘了跑 build」是一定會發生的事，而它的症狀是**三端裝到舊值而且沒有任何錯誤**。

## 為什麼 `tokens.js` 吐 `var(--x)` 而不是色碼

```js
brand: 'var(--brand)'      // ✅
brand: '#FAD6DC'           // ❌
```

吐原始值的話，JS 端會變成第二份**已經解析過**的真相 —— 那就回到今天的問題了。吐變數則是：日後真的要做深色模式，只要換 `:root`，JS 一行都不用改。

## 🔴 哪些圖進得來：品牌識別 vs 內容美術

判準**不是大小，是變更頻率**。

```
品牌識別   小熊（段位）、預設頭像、日後的 logo
           → 穩定、跨端、改了三端都要跟著改        → ✅ 收進這裡

內容美術   徽章、零食、活動 hero、教練熊、抽獎獎品
           → 隨活動更新、只有會員 App 有那個畫面    → ❌ 留在 migi-web
```

⚠ 如果活動圖進來，每換一張 hero 就是：改套件 → 打 tag → 三個 repo 都可能要 bump
—— **而其中兩個根本沒用到那張圖**。

📌 這條線與 CLAUDE.md 硬規則 10 是同一個分法：**「狀態」與「內容清單」是兩種東西**。
段位熊是**識別**（誰是誰），零食是**內容**（這一季餵什麼）。

🔴 待辦 33 已經預告：抽獎獎品池的美術是最大的成本（造型／房間／頭像共 38 項，分批上）。
**那批絕對不該進來** —— 它會讓這個套件變成每週要發版的東西，
而那正是硬規則 5.5 說的「要有人維護，而那個人不存在」。

## 🔴 兩件刻意**沒有**做成 token 的事

這兩個決定比「加了什麼」更重要。

### 一、字級的洞沒有補

```
現有 token   13  14  15  16  19  38
實際用到     10  11  12  13  14  15  16  17  18  20  22  24
```

看起來該補上缺的八個。**但那是錯的** ——

> **22 種字級是設計問題，不是 token 問題。**
> 世界級的字階是 6–9 階。把 22 個數字都給一個名字，等於**用 token 認可這個混亂**。

→ 保留現有 6 階。新寫的 UI 從這 6 階挑；真的挑不到，那是這一階該不該存在的問題，不是「再加一個 token」。

### 二、圓角的洞沒有補

```
現有 token   8  12  14  16  999
實際用到     9  10  11  12  13  14  18  99
```

同理。⚠ 特別注意 **`borderRadius: 99` 出現了 52 次**，而 `--r-pill: 999px` 就在那裡 —— **token 存在、大家要的就是它，但沒有人用**。原因是 POS 沒有那個 token。這正是這個套件要解決的事，不是再加一個 `--r-99`。

## 這一版新增的六個維度

| 維度 | 為什麼 |
|---|---|
| **`z` 層級** | 🔴 原本 8 個手挑的數字（1000/1050/1100/1200/1400/1600/2000/2100），含明顯是「我要蓋過那一個」的 1050／1400／1600。它**沒有錯誤訊息** —— 症狀是「彈窗被蓋住」，只有真的操作到那個組合才會發現 |
| **`borderWidth`** | `.5px` 與 `0.5px` 是同值兩種寫法 —— 那就是沒有名字的後果 |
| **`opacity`** | `.35`（鎖住）／`.45`（停用）／`.6`（次要）三個狀態各有語意但沒名字 |
| **`lineHeight`** | 87 處、15 種，完全沒有 token |
| **`letterSpacing`** | 17 處、5 種 |
| **`motion`** | 4 條手寫 cubic-bezier，其中一條只用過一次 |
| **`size.tapMin`** | POS 是平板、店員用食指。與 CLAUDE.md 待辦 10（平板沒有按壓回饋）是同一個關注點的兩半 |

## ⏳ 還沒收進來的

- **字型** `LXGW WenKai TC`（牌面國字用）——
  目前由 `migi-web/src/App.jsx` 動態注入 Google Fonts，**POS 與 admin 根本沒載**。
  🔴 要自己 host 之前必須先確認授權（我的理解是 SIL OFL，允許再散布與子集化，
  但**授權不能用猜的**）。中文字型還要 subset，不然是幾 MB。
- **語意色層**（`--text-secondary` → `--gray-1`）——
  `--ink` 用了 460 次、`--gray-1` 179 次，補語意層要逐一判斷 1000+ 個使用點各自是什麼用途，
  而**沒有工具能幫你判斷**。它真正的收益是換膚（深色模式、每店主色），而 MIGI 兩者都沒有。
  ✅ 折衷：`tokens.json` 的每個 token 都帶 `$description`，**先把意圖記下來**，
  改名是之後可以獨立決定的第二步。

## 遷移的原則

🎯 **第一版的成功標準是「新寫的 UI 有 token 可用」，不是「舊的全部改完」。**

三端加起來有 1000+ 個寫死值。一次改完是另一種災難 —— 而且**沒有任何驗證能證明它沒改壞**（那些只有畫出來才看得出來）。

| | 利息 | 要不要趁早 |
|---|---|---|
| **建立機制**（這個 repo） | 🔴 **複利** —— 每多寫一行 UI 就多一個要遷移的點 | ✅ 趁早 |
| **遷移既有的寫死值** | 🟢 **固定** —— 今天改一處跟明年改一處成本一樣 | ❌ 遇到再換 |
